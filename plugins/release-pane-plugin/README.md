# Release Pane Plugin

Shows the stages of a release build in a pane beside the chat, updating live while the release script runs: each stage with its status (pending, running, done, failed, skipped), its elapsed time and a short note. When a stage fails, the pane names it, shows the error and points to the stage's log (`build/archive.log`, `build/export.log`). When the run finishes, it shows the DMG and its size.

The pane opens by itself when a run starts in the session's project. `/release-pane` opens it at any time.

## How it works

The release script writes `build/release-status.json` at every stage boundary, and the plugin checks that file once a second. Any script that writes the file works, whatever its stages are. Scripts generated by the `mac-build-notarize` skill write it through `scripts/release-status.sh`.

In projects that never write the file, the plugin shows nothing.

## Status file

Times are in epoch seconds.

```json
{
  "runId": "1792844605-94129",
  "appName": "Rigly",
  "projectDir": "/path/to/project",
  "dryRun": true,
  "state": "running",
  "startedAt": 1792844605,
  "endedAt": null,
  "updatedAt": 1792844700,
  "version": "1.0.0",
  "dmgPath": "",
  "dmgSize": null,
  "waiting": "",
  "error": "",
  "stages": [
    { "id": "archive", "title": "Archive", "state": "running", "startedAt": 1792844610, "endedAt": null, "note": "", "log": "/path/to/project/build/archive.log" }
  ]
}
```

- `state` is `running`, `done` or `failed`. A stage's `state` is `pending`, `running`, `done`, `failed` or `skipped`.
- `waiting` is shown while the script waits for input in the terminal, such as a version number or a release title.
- `error` is the failure message, and `log` is the log file the pane points to when that stage fails.

## Settings

- **Status file** (`statusPath`): where the script writes the status file, relative to the project folder. The default is `build/release-status.json`.

## Install

```
/plugin install release-pane-plugin --marketplace memfrag/apparata-plugins
```
